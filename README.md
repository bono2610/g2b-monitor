# 나라장터 AI 사업 모니터(실습용 테스트)

조달청 나라장터 OpenAPI로 **AI·RPA·빅데이터 등 키워드 관련 입찰공고와 낙찰결과를 매일 자동 수집**하고, 대시보드로 보여주는 도구입니다.

- 서버 없음: GitHub Actions가 매일 수집 → 저장소에 저장 → GitHub Pages가 화면 제공
  (🔄 갱신 버튼을 쓰려면 Google Apps Script 웹 앱 1개만 추가 — 선택, 무료)
- 외부 LLM 없음: 키워드·제외어·분류 규칙(정규식)으로만 처리
- 공개 데이터만 다룸: 나라장터에 이미 공개된 공고·낙찰 정보

## 화면 구성
- 요약: 공고 건수 / 사업 규모 합계 / 낙찰 완료(낙찰총액·평균 낙찰률) / 최근 7일 신규
- **시도별 지도**: 시도별 건수·배정예산 합계를 파란색 5단계로 칠한 지도. 시도를 누르면 페이지 전체(요약·산점도·구간 카드·목록)가 그 지역으로 걸러지고 지역 드롭다운과 함께 움직입니다. 다시 누르거나 빈 곳을 누르면 해제
  - `전남광주`는 한 지역이라 광주·전남 경계를 같은 색으로 칠하고, 어느 쪽을 눌러도 `전남광주`가 선택됩니다
  - `중앙·기타`(기관명에 지명이 없는 공고)는 지도 아래 칸으로 따로 표시하고, 누르면 시도처럼 선택됩니다. 색 단계 계산에서는 뺍니다
  - 토글: **건수 / 금액**, **전체 / 지자체 사업만**(기관구분이 `지자체`인 공고만 — 페이지 전체 필터)
- **배정예산 vs 낙찰금액 산점도**: 낙찰완료 건, 점선은 낙찰금액 = 배정예산(100%). 선택 지역은 주황으로 강조. 점을 누르면 나라장터 원문. 큰 금액 몇 건 때문에 점이 몰리면 자동으로 로그 축(일반 축/로그 축 토글)
- **규모 구간별 평균 낙찰률**: 배정예산 1억 미만 / 1~5억 / 5~10억 / 10억 이상, 현재 필터 반영
- 차트: 월별 공고 건수, 발주기관 TOP 10(누르면 기관 검색)
- **🔄 갱신**: 누르면 바로 재수집(아래 "갱신 버튼 설정" 필요). 옆에 마지막 수집 시각 표시
- 목록: 상태(진행중·결과대기·낙찰), 분야·기관구분, 원문 링크, 낙찰업체·금액·낙찰률, 정렬
- **⬇ 엑셀 다운로드**: 현재 화면 필터 결과 목록 + `규모구간별낙찰률` 시트(현재 필터 기준)
- **📊 분석 엑셀 다운로드**: 필터와 무관하게 전체 데이터로 `나라장터_AI사업_분석자료_YYYYMMDD.xlsx` 생성
- **📝 보고서 초안 다운로드**: 숫자만 채운 .docx 보고서 초안 2종 (한글에서 열림)
- 데이터가 아직 없으면 가상의 샘플 데이터로 화면을 미리 보여줍니다.

### 분석 엑셀 시트 구성
| 시트 | 내용 |
|---|---|
| 안내 | 자료 기준일, 출처, 수집 키워드, 제외·중복 정리 기준, 용어(배정예산·낙찰률·지역 추정·분야 자동분류), 주의사항 |
| 공고목록 | 전체 공고 20개 열(상태~원문링크). 틀 고정·자동필터. **다른 시트의 집계는 모두 이 시트를 참조하는 수식** |
| 시도별비교 | 16개 시도(전남광주통합특별시 반영) + 중앙·기타 + 합계: 건수, 배정예산(백만원), 건당 평균, 낙찰 건수·금액, 평균 낙찰률, 예산·건수 순위. 도내(제주) 행 강조 |
| 도내현황 | 기관구분별 소계(건수·예산·낙찰·진행중·결과대기) + 사업 목록 + 중복 검토(같은 분야를 도내 다른 기관이 발주하면 "유사사업 있음") + 담당 부서 입력칸 |
| 사업비근거 | 분야별 건수·예산 기재 건수·평균·중앙값·최소·최대·낙찰 건수·평균 낙찰률(배정예산 0원 제외) + 챗봇·생성형AI·RPA 사례표 |
| 업체현황 | 낙찰 건수 상위 40개사 (내부 참고용) |
| 규모구간별낙찰률 | 배정예산 구간별 낙찰 건수·평균 낙찰률·예산/낙찰금액 합계, 지자체만 따로 (공고목록 참조 수식) |

- 수식은 COUNTIFS·SUMIFS·AVERAGEIFS·RANK와 배열수식 `{=MEDIAN(IF(...))}`만 씁니다. XLOOKUP·FILTER·UNIQUE 같은 최신 함수는 쓰지 않아 구버전 엑셀·한셀에서도 열립니다.
- 수식 결과값도 함께 저장되어 있어 재계산하지 않는 프로그램에서도 값이 보입니다.

### 보고서 초안 (.docx)
- ① **도내 AI 사업 추진현황**: 개요 / 도내 발주 현황(기관구분별 표·사업 목록) / 타 시도 비교(순위 표) / 시사점 / 자료 한계
- ② **○○사업 사업비 산정 근거**: 분야를 고르면 개요 / 분야별 사업비 분포 / 선택 분야 사례(배정예산순) / 적정 범위(안) / 유의사항
- 문장은 고정 템플릿에 숫자만 채웁니다. 예: "최근 약 3개월간 도내 기관이 나라장터에 낸 AI 관련 공고는 8건, 배정예산 37.2억원으로 16개 시도 중 건수 15위, 예산 12위입니다."
- **시사점·적정 범위처럼 해석이나 판단이 필요한 부분은 생성하지 않고 빈칸("담당자 작성")으로 둡니다.**
- 엑셀(ExcelJS)·워드(docx) 라이브러리는 버튼을 누를 때만 CDN에서 불러옵니다. 서버는 필요 없습니다.

## 설치 순서 (약 20분)

### 1) API 활용신청 — 공공데이터포털
아래 두 서비스를 각각 **활용신청**합니다. (일반 인증키 하나로 둘 다 사용)
- `조달청_나라장터 입찰공고정보서비스`
- `조달청_나라장터 낙찰정보서비스`

마이페이지 › 개발계정에서 **일반 인증키(Decoding)** 를 복사해 둡니다.

### 2) GitHub 저장소 만들기
1. 새 저장소 생성 (Public 권장 — 무료 계정은 Public 저장소만 Pages 사용 가능. 담긴 데이터는 모두 공개 정보입니다)
2. 이 폴더의 파일 전체를 업로드 (`.github` 폴더 포함)

### 3) API 키 등록 — Secrets
저장소 › Settings › Secrets and variables › Actions › **New repository secret**
- Name: `G2B_SERVICE_KEY`
- Secret: 복사한 인증키

> 키는 Secrets에만 넣고, 코드나 config.json에는 절대 쓰지 마세요.

### 4) 화면 켜기 — Pages
Settings › Pages › Source: **Deploy from a branch** › Branch: `main` / `(root)` › Save
→ 1~2분 뒤 `https://<아이디>.github.io/<저장소명>/` 에서 대시보드가 열립니다.

### 5) 첫 수집
Actions 탭 › **나라장터 공고 수집** › Run workflow › backfill 칸에 `90` 입력 › 실행
→ 최근 90일 공고가 쌓입니다. 이후에는 매일 오전 6시 47분에 자동으로 최근 3일치를 갱신합니다.

## 갱신 버튼 설정 (선택)
화면의 **🔄 갱신** 버튼은 이렇게 동작합니다.

```
버튼 → Google Apps Script 웹 앱(relay/apps-script.gs) → GitHub Actions '나라장터 공고 수집' 실행(workflow_dispatch)
     → 수집·커밋 → GitHub Pages 배포 → 화면이 15초마다 data/bids.json 을 확인하다가 바뀌면 자동으로 다시 그림
```

- GitHub 토큰은 **Apps Script의 스크립트 속성에만** 둡니다. 페이지·저장소에는 토큰이 없습니다.
- 마지막 실행(매일 예약 실행 포함) 후 30분 안에는 다시 실행하지 않고 "N분 후 다시 가능"이라고 답합니다. 이미 수집 중이면 새로 실행하지 않습니다. (GitHub 실행 기록으로 판단, DB 없음)
- 5분이 지나도 데이터가 안 바뀌면 "수집이 지연되고 있어요" 안내가 나옵니다. Actions 탭에서 실행 결과를 확인하세요.
- Apps Script 웹 앱은 응답 헤더를 정할 수 없어 **호출 출처(CORS) 제한은 걸 수 없습니다.** 주소를 아는 누구나 부를 수 있지만, 30분 쿨다운과 토큰 권한(이 저장소 Actions만)이 남용을 막습니다. 출처 제한이 꼭 필요하면 아래 "Vercel로 할 때"를 쓰세요.

### 1) GitHub 토큰 발급 (fine-grained, 권한 최소)
1. GitHub 오른쪽 위 프로필 › **Settings** › 맨 아래 **Developer settings** › **Personal access tokens** › **Fine-grained tokens** › **Generate new token**
2. Token name: `g2b-relay` / Expiration: 원하는 기간(예: 1년 — 만료되면 새로 발급해 스크립트 속성 값만 바꾸면 됩니다)
3. Resource owner: 본인 계정 / Repository access: **Only select repositories** › `g2b-monitor` 하나만 선택
4. Permissions › Repository permissions › **Actions: Read and write** 하나만 켭니다 (Metadata: Read-only는 자동으로 붙음). 다른 권한은 모두 No access
5. **Generate token** › 나온 값(`github_pat_…`)을 복사 (이 화면을 벗어나면 다시 볼 수 없음). 어디에도 붙여 넣지 말고 아래 스크립트 속성에만 넣으세요

### 2) Apps Script 웹 앱 만들기
1. https://script.google.com › **새 프로젝트** › 위쪽 제목을 `g2b-relay` 로 변경
2. `Code.gs` 내용을 모두 지우고 저장소의 [`relay/apps-script.gs`](relay/apps-script.gs) 내용을 그대로 붙여 넣기 › 💾 저장
3. 왼쪽 **⚙ 프로젝트 설정** › 맨 아래 **스크립트 속성** › **스크립트 속성 추가**
   - 속성: `GITHUB_TOKEN` / 값: 1)에서 복사한 토큰 › **스크립트 속성 저장**
4. 왼쪽 **< > 편집기**로 돌아와 위쪽 함수 선택 칸에서 **`checkStatus`** 고르고 **▶ 실행**
   - "승인 필요" › 권한 검토 › 본인 계정 › ("Google에서 확인하지 않은 앱" 이 나오면 **고급** › **g2b-relay(으)로 이동(안전하지 않음)**) › **허용**
     (본인이 만든 스크립트라 나오는 경고입니다. 요청 권한은 "외부 서비스에 연결" 하나)
   - 아래 실행 로그에 `{"status":"ready",…}` 또는 `{"status":"cooldown",…}` 이 나오면 정상
5. 오른쪽 위 **배포** › **새 배포** › ⚙(유형 선택) › **웹 앱**
   - 설명: `g2b-relay` / 다음 사용자 인증 정보로 실행: **나** / 액세스 권한이 있는 사용자: **모든 사용자**
   - **배포** › 나온 **웹 앱 URL**(`https://script.google.com/macros/s/…/exec`) 복사
6. 확인: 그 주소를 브라우저 주소창에 열면 상태 JSON이 보입니다 (주소창으로 여는 건 상태만 보고 실행하지 않음)

> 코드를 고친 뒤에는 **배포 › 배포 관리 › ✏ 수정 › 버전: 새 버전 › 배포** 로 올려야 같은 주소에 반영됩니다. (새 배포를 만들면 주소가 바뀜)
> 저장소·쿨다운을 바꾸려면 코드 위쪽 `REPO`, `WORKFLOW`, `REF`, `COOLDOWN_MIN` 값을 고칩니다.

### 3) 페이지에 중계 주소 넣기
`config.json` 의 `refresh_relay_url` 한 줄만 고쳐 커밋합니다.
```json
"refresh_relay_url": "https://script.google.com/macros/s/AKfy…/exec",
```
1~2분 뒤 Pages 가 다시 배포되면 버튼이 동작합니다. 비워 두면 버튼을 눌러도 "아직 설정되지 않았어요" 안내만 나옵니다.

### (대안) Vercel로 할 때
`relay/api/refresh.js` 는 같은 동작을 하는 Vercel 서버리스 함수이며, `https://bono2610.github.io` 출처만 허용(CORS)합니다.
Vercel › Add New › Project › 이 저장소 Import › **Root Directory: `relay`** › Environment Variables `GITHUB_TOKEN` › Deploy › `https://<주소>/api/refresh` 를 `refresh_relay_url` 에 넣으면 됩니다.

## 설정 바꾸기 (`config.json`)
| 항목 | 의미 |
|---|---|
| `keywords` | 수집할 공고명 키워드. 바꾸면 다른 주제 모니터링기가 됩니다 |
| `exclude_keywords` | 공고명에 있으면 제외할 단어 |
| `exclude_patterns` | 공고명이 걸리면 제외할 정규식 (예: 조류인플루엔자(AI) 진단키트) |
| `home_region` | 분석 엑셀 '도내현황'과 보고서에서 '도내'로 볼 시도 (기본 `제주`) |
| `region_rules` | 수요기관명 → 시도 추정 규칙 |
| `field_rules`, `field_default` | 공고명 → 분야 분류 규칙 |
| `kind_rules`, `kind_default` | 수요기관명 → 기관구분 규칙 |
| `stats_exclude_fields` | 사업비 통계에서 뺄 분야 (기본: 단가계약) |
| `similar_check_exclude_fields` | 도내현황 '중복 검토'에서 비교하지 않을 분야 |
| `dedup_strip_pattern` | 중복 정리 때 공고명에서 지우고 비교할 표시어 (재공고·정정공고 등) |
| `bid_types` | `용역`, `물품`, `공사` 중 선택 |
| `daily_lookback_days` | 매일 다시 훑는 기간(정정공고·낙찰 반영용) |
| `backfill_days` | 데이터가 비었을 때 처음 가져오는 기간 |
| `refresh_relay_url` | 🔄 갱신 버튼이 부르는 중계 주소 — Apps Script 웹 앱 `/exec` 주소 (위 "갱신 버튼 설정") |

영문 약어 키워드(AI, RPA 등)는 앞뒤가 영문자일 때(MAIL, TRAIN, AIR 등) 자동으로 걸러집니다.

## 분류 규칙 고치는 법
지역·기관구분·분야는 **수집기가 `config.json` 규칙으로 계산해 `data/bids.json`에 저장**합니다. 화면·분석 엑셀·보고서는 이 값을 그대로 쓰므로 기준이 하나로 맞춰집니다.

1. `config.json`을 고칩니다. 규칙은 모두 정규식이고 **위에서부터 먼저 걸리는 것**이 적용됩니다.
   - 분야 추가·순서 변경: `field_rules`에 `["분야명", "키워드1|키워드2"]`를 원하는 위치에 넣습니다.
   - 기관구분: `kind_rules`도 같은 방식입니다. 같은 구분을 여러 줄에 써도 됩니다.
   - 제외 공고 추가: `exclude_patterns`에 정규식 한 줄을 추가합니다.
   - 지역이 틀린 기관: `region_rules.overrides`에 `"기관명 정규식": "시도"`를 넣으면 가장 먼저 적용됩니다.
     (예: `"^경북대학교": "대구"` — 본교 소재지 기준)
   - 시도를 합치거나 나눌 때는 `region_rules`의 `order`·`official`·`patterns`를 함께 고칩니다. 시도 수와 순위·문장의 "○개 시도"는 `order`를 따라 자동으로 바뀝니다.
   - 시 이름 오탐: `region_rules.patterns`에서 정규식으로 막습니다. (예: `"(?<!연)수원"`은 '연수원'을 수원으로 보지 않음)
2. API를 다시 부르지 않고 기존 데이터에 바로 적용합니다.
   ```bash
   python collector/collect.py --reprocess
   ```
   제외 건수, 중복 정리 전후 건수, 지역별 건수 변화가 출력됩니다.
3. `config.json`과 `data/bids.json`을 함께 커밋하면 화면에 반영됩니다. (규칙만 커밋해도 다음 날 자동 수집 때 적용됩니다)

### 지역 추정 순서
1. `overrides` (정규식 → 시도)
2. 수요기관명이 시도 정식명칭(서울특별시, 경기도, 제주특별자치도 등)으로 시작하면 그 시도로 확정
3. 아니면 기관명에서 **가장 앞에 나오는** 지명(`patterns`)의 시도
4. 수요기관에서 못 찾으면 공고기관을 보되, `조달청 ○○지방조달청` 같은 구매 대행기관은 보지 않음
5. 그래도 없으면 `중앙·기타`

> 예전에는 수요기관과 공고기관을 이어 붙인 뒤 규칙 순서대로 찾아서, 수요기관이 "경기도 수원시"이고 공고기관이 "조달청 인천지방조달청"이면 `인천`으로 잡혔습니다.

> **광주광역시와 전라남도는 2026.7.1. 전남광주통합특별시로 통합**되어 한 시도 `전남광주`로 봅니다. 수요기관명이 `전남광주통합특별시`·`광주광역시`·`전라남도`로 시작하거나 광주·전남 지명이 나오면 모두 `전남광주`입니다. 통합 전(2026.6.30. 이전) 공고를 옛 시도로 나눠 보려면 `order`·`official`·`patterns`에 `광주`·`전남`을 다시 나눠 넣으세요.

### 중복 정리
공고명(공백 정리, `(재공고)`·`[재공고]` 같은 표시 제거)과 수요기관이 같거나, 공고번호가 같은 공고(정정 차수)를 1건으로 묶습니다. 대표 공고는 낙찰 결과가 있는 공고, 없으면 최신 공고일 공고입니다. 묶인 건수는 `dups`, 묶인 공고 id는 `dupIds`에 저장되고, 묶인 공고번호로 들어온 낙찰 정보도 대표 공고에 연결됩니다.

## 알아둘 점
- **지역·기관구분·분야는 추정값**입니다. 규칙은 위 "분류 규칙 고치는 법" 참고. 보고 전에는 원문을 확인하세요.
- **낙찰 연결**은 공고번호 기준입니다. 낙찰 API를 같은 키워드로 조회해 이미 수집된 공고에 붙입니다.
- API는 한 번에 1개월 이내만 조회되므로 수집기가 28일 단위로 나눠 호출합니다.
- 인증키 오류 등으로 **모든 호출이 실패하면 기존 데이터를 덮어쓰지 않고** 작업이 실패로 끝납니다. (Actions 탭에서 확인)
- 활용신청 직후에는 키가 등록되기까지 1시간 정도 걸릴 수 있습니다 (`SERVICE_KEY_IS_NOT_REGISTERED_ERROR`).

## 지도 데이터 (출처)
`data/geo/sido.topo.json` (약 35KB)은 아래 행정동 경계를 시도별로 합치고 단순화한 TopoJSON입니다. 외부 CDN 없이 저장소 파일을 그대로 씁니다.

- 원자료: **통계청 SGIS 행정구역 경계** (공공누리 제1유형, 출처표시)
- 가공: **[vuski/admdongkor](https://github.com/vuski/admdongkor)** `ver20261001` 행정동 경계 (CC BY 4.0) — 2026.7.1. 전남광주통합특별시 출범, 2023.7.1. 군위군 대구 편입, 세종 포함
- 이 저장소에서 한 가공: 시도 단위 병합(dissolve), 전남광주는 옛 광주광역시 5개 구(`part: 광주`)와 나머지(`part: 전남`) 두 도형으로 나눔(값·색은 `region: 전남광주` 하나로 같음), 2% 단순화([mapshaper](https://github.com/mbloch/mapshaper))

다시 만들 때 (원본 GeoJSON 약 35MB를 받은 폴더에서):
```bash
npx mapshaper HangJeongDong_ver20261001.geojson \
  -each 'var S={"11":"서울","26":"부산","27":"대구","28":"인천","30":"대전","31":"울산","36":"세종","41":"경기","51":"강원","43":"충북","44":"충남","52":"전북","12":"전남광주","47":"경북","48":"경남","50":"제주"}; region=S[sido]; part = sido=="12" ? (["동구","서구","남구","북구","광산구"].indexOf(sggnm)>=0 ? "광주" : "전남") : region' \
  -dissolve2 part copy-fields=region name=sido -simplify 2% keep-shapes -filter-slivers \
  -o format=topojson quantization=10000 data/geo/sido.topo.json
```
지도 속성 `region` 은 `config.json` 의 `region_rules.order` 시도명과 같아야 색이 칠해집니다. 시도를 합치거나 나누면 `region` 값도 맞춰 주세요.
